# 배포 사이트 피드백 예약 전송

## 구성과 데이터 보존

- Vercel Production + 기존 Neon 영구 저장소 + QStash Free의 지연 메시지를 사용한다. Redis/Firebase 전환, 공용 예시 초기화, 화면 변경은 없다.
- 로컬에서는 기존 파일 저장소 작업자가 동작한다. Production에서는 브라우저/로컬 PC가 꺼져 있어도 QStash가 서명된 POST로 서버를 호출한다.
- 예약 정책 검증 → QStash 등록 → 기존 CAS 저장 순서다. 큐 등록 실패는 예약 성공으로 응답하지 않는다. 저장 직전 정책을 다시 검증하며 취소·초기화·경합으로 불필요해진 큐 작업은 무시한다.
- 메시지에는 암호화된 환경·저장소·세션·예약 식별정보만 포함된다. 글, 피드백, 학생명, 브라우저 소유 쿠키는 전송하지 않는다.
- 테스트 작업은 해당 브라우저 저장소의 해당 세션에만 반영된다. 개별 초기화로 세션 토큰이 바뀌면 이전 작업으로 새 예시를 수정할 수 없다.
- 서명 검증(현재/다음 키), 환경 구분, 예약 nonce, 원자적 CAS, 기존 전송/권수/학부모 처리 함수를 사용한다. 중복 호출은 중복 전송·차감을 하지 않는다.
- 전송 조건 실패는 기존 실패 상태로 남으며 자동 재전송하지 않는다. 일시적인 서버 연결 오류만 제한적으로 재호출하고, 재호출 소진 시 서명된 실패 콜백으로 실패 이력을 기록한다.

## Production 비밀 환경변수

`QSTASH_URL`, `QSTASH_TOKEN`, `QSTASH_CURRENT_SIGNING_KEY`, `QSTASH_NEXT_SIGNING_KEY`, `DOKDO_FEEDBACK_SCHEDULE_KEY`(32바이트 hex), `DOKDO_FEEDBACK_SCHEDULE_ORIGIN`(운영 HTTPS origin).

기존 `DOKDO_STATE_PROVIDER=neon`, Production `DOKDO_STATE_NAMESPACE`를 그대로 사용한다. Preview에는 운영 키를 설정하지 않는다. 암호화 키는 대기 작업이 남아 있는 동안 임의 교체하지 않는다. 키 값은 Git·로그·API 응답에 기록하지 않는다.

## 무료 한도와 운영 주의

- QStash Free: 하루 1,000회 메시지 전달(재호출·실패 콜백 포함), 메시지별 최대 지연 7일. 7일보다 먼 예약은 6일 단위 확인으로 이어가며 사용자가 지정한 예약일은 변경하지 않는다.
- 유료 플랜 전환/카드 등록/추가 과금 설정은 하지 않는다. 한도 초과·공급자 장애로 새 등록이 거절되면 오류를 표시하고 기존 데이터를 유지한다.
- 매분 전체 DB를 조회하는 Cron은 사용하지 않는다. 빈 시간대에는 Neon을 깨우지 않는다.
- 무료 서비스에는 정시 실행 SLA가 없다. 공급자/네트워크 장애 시 지연될 수 있으며 실제 성공 시각을 기존 정책의 전송 시각으로 저장한다.
- 원본 처리와 실패 콜백 모두 장시간 실패하면 QStash DLQ와 서버 로그를 확인해야 한다. 무한 재전송이나 유료 전환은 하지 않는다.

## 기존 대기 예약 연결 (배포 후 1회)

QStash Request Builder에서 운영 `/api/internal/feedback-schedules/connect-existing`로 POST한다. 본문은 `{"operation":"connect-existing","run":"deployment-고유식별자"}`다. 이 경로도 QStash 서명을 필수 검증한다.

현재 환경의 공용/브라우저별 저장소를 작은 페이지로 읽고, 연결되지 않은 대기·처리 중 예약에 큐 연결 정보만 추가한다. 완료·취소·실패 예약, 예시 구성, 작성 내용, 기존 이력은 덮어쓰지 않는다. 다음 페이지는 자체 연결하며 동일 요청을 다시 보내도 이미 연결된 예약은 건너뛴다. 지정일 시계는 실제 시각으로 바꾸지 않는다.

## 확인

- 일반 목록의 박서준(예약 대기)·이하린(예약 실패) 예시는 로컬과 Vercel Production에서 같은 생성 함수를 사용한다. 운영 데이터 전체를 초기화하거나 로컬 파일을 복사하지 않고, 누락된 두 예시만 추가한다. Preview·다른 namespace·지정일 시계에는 추가하지 않는다.
- 배포 예시의 대기 예약도 QStash 등록 후 저장한다. 이후 조회는 취소·실패·전송 결과를 덮어쓰지 않으며, 명시적 예시 초기화 때만 초기 상태를 복원하고 새 예약을 연결한다. 브라우저별 전용 테스트 저장소에는 접근하지 않는다.
- 목록은 `피드백 작성 완료`와 `예약 전송 대기`/`예약 전송 실패`만 표시하며, 일시는 상세에서 확인한다.

- `npm test`, 변경 파일 ESLint, `npm run build`
- 별도 브라우저 소유 테스트 예시로 1차 완료/2차 요청/2차 완료를 예약한 뒤 페이지 요청 없이 대기하여 실제 전송 시각·권수·학부모 결과를 확인한다.
- 취소/개별 초기화/중복/서명 오류/다른 브라우저/고정 시계/장기 예약/연결 실패 검증은 전용 자동 테스트로 확인한다.
- 배포 후 Vercel Ready와 목록·상세·주간 관리·학생 화면을 확인한다. QStash 메시지에 개인 정보가 없는지 확인한다.
